# CLAUDE.md

Guidance for AI assistants working in this repository. Read this before making changes.

## What Euclid is

Euclid is a browser-based, installable (PWA) **synthesised drum machine + melody sequencer**
built around Euclidean rhythms. It has no backend: everything runs client-side, saves to
`localStorage` and to JSON files, and exports audio as WAV. The whole app is a single-page
TypeScript app bundled by Vite and deployed to GitHub Pages.

The core idea: six coloured **voices** (rings), each carrying rhythms whose hits are spread
evenly across a number of steps (the Euclidean algorithm). Each voice hosts a procedural
list of **loops** (a sound + rhythm + a placement rule saying where on the timeline it
lands), plus one voice hosts a **melody**. Sounds are generated by a full synthesis engine
running in an AudioWorklet.

## Tech stack & commands

- **Language:** TypeScript (strict mode), no framework — the UI is hand-rolled DOM.
- **Bundler/dev server:** Vite 5.
- **Runtime:** browser Web Audio API; DSP in an AudioWorklet.
- **No test suite, no linter config, no formatter config.** Type-checking via `tsc` is the
  only automated gate (run as part of `build`).

```bash
npm install        # install deps
npm run dev        # Vite dev server with HMR (host exposed for phone testing)
npm run build      # tsc (typecheck, noEmit) THEN vite build -> dist/
npm run preview    # serve the production build locally
```

Before committing, run `npm run build` — it typechecks the whole `src/` tree. `tsconfig.json`
enables `strict`, `noUnusedLocals`, and `noUnusedParameters`, so unused code fails the build.

Node 20 is used in CI (`.github/workflows/deploy.yml`).

## Architecture: the two worlds

The single most important thing to understand is the **main-thread / AudioWorklet split**.

### 1. Main thread (`src/`, TypeScript, bundled)
Owns all UI, the data model, save/load, and the parameter definitions (ranges, defaults,
groupings). It computes rhythms, compiles the track into engine "lanes", and sends the
worklet plain messages: a **sound table**, **voice lines**, tempo, transport commands.

### 2. AudioWorklet (`public/worklet/engine.js`, plain JS, served verbatim)
The DSP. It is a **hand-maintained plain-JavaScript file** — NOT bundled or transformed by
Vite. It runs in `AudioWorkletGlobalScope`, so it must be self-contained with **no imports**.
It is a port of a C++ engine (see its header). `vite.config.ts` uses `base: "./"` and the
worklet is loaded by URL at runtime (`src/audio/engineHost.ts`) so its path survives being
hosted from a subfolder.

**Critical invariant — parameter indices must stay in sync.** The main thread sends each
sound as a fixed-length flat `number[]` snapshot. The array index of each parameter is
defined by `ParamId` in `src/model/params.ts`, and the worklet reads those same indices from
its `P = {...}` map at the top of `public/worklet/engine.js`. **If you add, remove, or
reorder a parameter, you MUST update both `src/model/params.ts` (the `ParamId` enum) and the
`P` map in `public/worklet/engine.js` identically**, plus `NUM_PARAMS`, the param spec in
`src/model/paramSpec.ts`, and any expansion lookup tables the worklet mirrors from
`paramSpec.ts` (choice lists like `CRUSH_BITS`, `NOISE_TYPES`, `LFO_TARGETS`, etc.). The
source comments describe a "check script" that asserts the match — treat this as an invariant
you verify by hand; there is currently no such script in the repo.

`EngineHost` (`src/audio/engineHost.ts`) is the ONLY bridge to the worklet. All DSP messaging
goes through it (`setSounds`, `setLines`, `setTempo`, `setSection`, `play`, `stop`,
`audition`, `renderToBuffer`, etc.). It also handles the messy realities of Web Audio:
AudioContext must be started from a user gesture; iOS suspends/kills the context in the
background (`ensureRunning()` rebuilds it and signals the caller to re-push all state).

## Key domain concepts

- **Voice / colour / line:** there are `NUM_LINES = 6` voices (`src/model/lines.ts`), one per
  ring and per letter of the logo, each with an identity colour in `VOICE_COLORS`. One of the
  six rows hosts the melody instead of loops (`MELODY_COLOR_INDEX`).
- **Euclidean rhythm** (`src/model/euclid.ts`): `hits` triggers spread evenly across `steps`,
  downbeat on step 0, then rotated by `rotation`. `splitPattern`/`voicePattern` allow uneven
  custom gaps. `MAX_STEPS = 64`.
- **Loop** (`src/model/track.ts`): a sound + rhythm + a **placement rule** (`EveryRule`:
  weight / dice / every-Nth / power-of-2 / explicit bars / fill), a sounding length in bars,
  and overlap-vs-solo stacking. Rules are seeded so weighted rolls are reproducible.
- **Track & compile** (`src/model/track.ts`): the authoring surface is a `Track` (bar limit +
  six `ColorTrack`s of loops + a melody list). `compile()` flattens it into the engine's
  `VoiceNode` chains ("lanes") that everything downstream (engine, WAV export, rings) runs on.
- **Node / transition** (`src/model/lines.ts`): a node is one sound + one rhythm repeated
  `reps` times, optionally with a lead-in wait and an intro/outro **transition** (a fade or
  morph folded into the node's own window). `TransitionMode` covers morph/crossfade/filter/
  fade/wash/thin/drive/crush/echo/speed; rows can also carry overarching `RowSweep`s.
- **Sound / snapshot:** a sound is a `number[]` of `NUM_PARAMS` values, one per `ParamId`.
  There are **no presets** — every sound is a generic full-range sound; the shuffle draws each
  param from its full base range (`paramSpec.baseRange`). `drumKit.ts` owns shuffle + undo.
- **Save format:** `project.ts`, JSON `version: 13`. **Only version 13 loads**; any other
  version loads a blank track and the DEFAULT drum kit — only the tempo is restored. (The
  kit is version-gated too because v13 shifted the snapshot indices, so an older kit
  snapshot would land on the wrong params.) The format is
  deliberately NOT back-compatible with earlier generations. Every field is validated on load
  (`read*` helpers) so malformed/partial saves degrade gracefully. `localStorage` key is
  `"msq010.project"` (kept from the working title so old saves keep loading).

## Conventions & house style

- **Comments carry the design rationale.** Files open with a substantial header comment
  explaining the *why*, and tricky invariants are commented inline. Match this density: when
  you change behaviour, update the surrounding prose, and explain non-obvious decisions the
  way the existing comments do.
- **No framework, no JSX.** UI is built with direct DOM APIs. Follow the patterns already in
  `src/ui/`.
- **`model/` is DOM-free** pure logic; **`ui/` owns all rendering**; **`audio/` bridges to Web
  Audio**. Keep that separation.
- **Determinism via seeds.** Shuffles, placements, and melody generation are seeded so results
  reproduce and support undo (`seedHistory`). Use `src/model/rng.ts` for shared randomness.
- **Strict TS.** No unused locals/params; the build fails otherwise. Prefer explicit,
  descriptive names consistent with neighbours.
- **`app.ts` is intentionally large (~6k lines)** and is the coordination hub. `recompile()`
  is the pipeline that turns the track into engine lanes and re-pushes state; most edits flow
  back through it. Read the region you're touching before editing.

## When you change things — checklists

**Adding/changing a synth parameter:** update `ParamId` + `NUM_PARAMS` in `params.ts`, the
spec in `paramSpec.ts`, the `P` map (and any mirrored choice tables) in
`public/worklet/engine.js`, wire the DSP in `engine.js`, surface it on a Graph-mode trace in
`soundTraces.ts` (the formula's `vars`/`types`, and the `code` snippet quoting the engine),
and add help text in `soundHelp.ts`. If the snapshot layout changes, bump the save `version`
in `project.ts` — snapshots are stored in saved projects, so reordering breaks existing saves.

**Changing the save format:** bump the `version` in `project.ts`, decide the load policy for
old versions (current policy: refuse — load blank), and update `serialize`/`deserialize` plus
the `read*` validators together.

**Touching the DSP:** remember `engine.js` is plain JS, no imports, served verbatim, and mirrors
main-thread param indices. It is also used offline for WAV export via
`EngineHost.renderToBuffer` (config passed through `processorOptions`, not port messages, to
avoid a startup race).

## Git & deployment

- **Deployment is automatic:** pushing to `main` runs `.github/workflows/deploy.yml`
  (`npm ci` → `npm run build` → deploy `dist/` to GitHub Pages).
- **The service worker** (`public/sw.js`) makes HTML navigations and the worklet network-first
  (the worklet has a fixed, non-hashed filename) so a new deploy shows up on the next online
  reload instead of being pinned to a stale cache. Keep that behaviour if you edit `sw.js`.
- **`.claude/` is gitignored**, along with `node_modules/`, `dist/`, `*.local`, `.DS_Store`,
  and the agent-skill tooling (`.agents/`, `skills-lock.json`).
